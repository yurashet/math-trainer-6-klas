# Спека: §-узроўневая прывязка матэматычнага трэнажора

**Статус:** гатова да рэалізацыі, версія 1.1 (freeze) · **Дата:** 2026-11-26 · **Аўтар:** БА
**Адрасаты:** aidev → `generators.js`; front → `index.html` + `app.js`; back → `docs/schema`; uxui → `docs/design`; tester → QA.
**Крыніца ісціны па §§:** `docs/SUBS.md` — 6 раздзелаў, 38 §§. Гэтая спека **не дадае, не выдаляе і не пераймяноўвае** §§: яна дадае кароткія назвы для UI і поўны пералік патрэбных генератараў.
**Прынцып:** спека — адзіная кропка праўды паміж выканаўцамі. Калі спека супярэчыць іншай картцы — перамагае спека; непаразуменні вырашае БА праз каментар у картцы (не перайрашаць самастойна).
**Гісторыя змен:** 1.0 — базавая спека; 1.1 — адкалібраваныя парогі харнеса (q 5..300, hint 6..200, межы лікаў у `hint`, дужкі мностваў `{3, 10}` дазволеныя). Патрабаванні да генератараў і матрыца не змяніліся.

## 0. Кантэкст і зафіксаваныя рашэнні

**Што ёсць зараз (праверана па кодзе):**

* `docs/SUBS.md` — 38 §§: decimals 10, percent 7, sets 4, rational 9, coords 3, geometry 5. Для кожнага § апісаны тып задачы і мэтавы лікавы адказ.
* `app.js` — 41 генератар (`gAddDec … gSymmetry`) і мапа `GEN: chapter → [fn]`. §-ключа няма наогул.
* `chooseQuestion(scope)` разумее толькі id раздзела або `'mix'` і бярэ ўзровень з `S.topics[topicId]`; для `'decimals:S3'` гэта `undefined` → выключэнне.
* `parseAns` выдаляе ўсе сімвалы, акрамя `[0-9.\-]`, таму `−5` (U+2212) ператвараецца ў `5`, а `1-2` — у `1`.
* `index.html` падключае толькі `app.js`; `generators.js` не існуе.

**Мэта змены:** двух'узроўневы выбар «раздзел → § або «Усе §»» з гарантаваным пакрыццём 38/38 §§ і захаваннем прагрэсу па кожным §.

## 1. Мэты, не-мэты, паказчыкі

**Мэты**

* **G1. §-выбар.** З галоўнай за ≤2 клікі вучань трапляе ў сесію па канкрэтным §.
* **G2. Пакрыццё.** 38/38 §§ маюць ≥1 генератар (мэта ≥2), 0 памылак у 38 §-сесіях.

## 3. Кананічныя фарматы

### 3.1 Граматыка scope

```
scope    := 'mix' | chapter | chapter ':' S<N>
chapter  := 'decimals' | 'percent' | 'sets' | 'rational' | 'coords' | 'geometry'
S<N>     := 'S' [1-9] [0-9]?          // без вядучых нулёў, 1..N раздзела
```

`'mix'` — не §, а рэжым змяшанай трэніроўкі. Кананічны запіс — `chapter` (увесь раздзел) або `chapter:SN` (канкрэтны §), напрыклад `decimals:S3` або `decimals`; у тэксце задачы «`chapter`» — гэта **метапазначэнне**, а фактычна ў `startSession` перадаецца id раздзела, напрыклад `startSession('decimals')`.

**Нармалізацыя** (абавязковая перад любой аперацыяй са scope):

```
normalizeScope(raw):
  s = String(raw == null ? '' : raw).trim()
  if (s === 'mix') return 'mix'
  s = s.replace(/\s+/g, '')
  m = /^([a-z]+)(?::[Ss]?0*(\d{1,2}))?$/.exec(s)
  if (!m) return null
  ch = m[1]; if (!SUBS[ch]) return null
  if (m[2] === undefined) return ch
  sn = 'S' + Number(m[2])
  if (!SUBS[ch].some(x => x.id === sn)) return null
  return ch + ':' + sn
```

| Увод | Вынік | Каментарый |
|---|---|---|
| `decimals` | `decimals` | увесь раздзел |
| `decimals:S3` | `decimals:S3` | кананічны |
| ` decimals : s03 ` | `decimals:S3` | трыманне, рэгістр, вядучы нуль |
| `rational:S9` | `rational:S9` | апошні § раздзела (у ім 9 §§) |
| `rational:S10` | `null` | за межамі N |
| `geometry:S0` | `null` | нумары пачынаюцца з 1 |
| `algebra:S1` | `null` | невядомы раздзел |
| `mix` | `mix` | рэжым |

### 3.4 Кантракт генератара

```js
fn(d: number) -> { q: string, a: number, hint: string }
```

| Поле | Патрабаванні |
|---|---|
| `q` | радок 5..300 сімвалаў, беларуская мова, адзінкі вымярэння ў пытанні («(см²)», «(руб.)»), без незапоўненых маркераў шаблону выгляду `{a}` ці `{N}` (фігурныя дужкі для запісу мностваў — `{3, 10, 8}` — дазволеныя), без `NaN`/`undefined`/`Infinity`/экспаненты |
| `a` | канечны лік, `\|a\| ≤ 1 000 000`, цэлы або ≤2 знакі пасля коскі (`decimals:S9` — ≤3; `decimals:S5` — ≤4) |
| `hint` | радок 6..200 сімвалаў, апісвае **метад** рашэння; не змяшчае адказ **асобным лікам** (правяраецца пры `\|a\| ≥ 20` з межамі разрадаў: «13» не з'яўляецца часткай «130», «80» — часткай «180°»); калі гэты лік ужо прысутнічае ва ўмове як дадзенае (аперацыйны лік), гэта дапушчальна; не паўтарае `q` |
| `d` | 1..10, абавязковы clamp унутры функцыі (`d = Number(d) \|\| 3; d = Math.max(1, Math.min(10, d))`), ніколі не кідае выключэнне |

Забаронена: DOM, `localStorage`, чытанне/запіс глабальных зменных, залежнасць ад іншых генератараў, `alert/confirm`, сеткавыя выклікі, `eval`.

Імя функцыі — гэта яе ID з матрыцы (§4), напрыклад `function dec_s3_ray_value(d) {…}`. Гэта дазваляе супаставіць код і спеку; харнес папярэджвае, калі імя не супадае.

**Антыпрыклады → правільна:**

| Дрэнна | Чаму | Як трэба |
|---|---|---|
| `a: "12,5"` | адказ радком | `a: 12.5` |
| `q: 'Плошча круга?'` + `a: 3.14*r*r` без акруглення | 3+ знакі, float-смецце | `a: r2(3.14*r*r)` |
| `hint: 'Адказ 12,5'` | выдае адказ | `hint: 'Памнож радыус на 2 і на 3,14.'` |
| `q` з `{a}` | шаблон не запоўнены | канкатэнацыя значэння ў радок |
| адзін шаблон на ўвесь § | зубрэнне | 2+ генератары і выпадковыя параметры (≥20 розных `q` на 200 розыгрышаў) |

### 3.5 Адказ, акругленне, допуск

* `dp(a)` — колькасць знакаў пасля коскі ў дзесятковым запісе `a`.
* `ε(a) = 0,5 · 10^(−max(dp(a), 2))`, правільна калі `|inp − a| ≤ ε(a) + 1e-9`.

| `a` | `ε` | Прыклад |
|---|---|---|
| 12 | 0,005 | «12» і «12,00» — так, «11,99» — не |
| 12,5 | 0,005 | «12,5» — так, «12,49» — не |
| 0,75 | 0,005 | «0,75» — так, «0,7» — не |
| 0,125 | 0,0005 | «0,125» — так, «0,13» — не |

Цяперашні допуск 0,02 у `app.js` **замяняецца** на гэтае правіла (DEC-5).

### 3.6 Правілы ўводу (`parseAns`)

```
parseAns(v):
  if (v == null) return NaN
  t = String(v).trim()
  if (/[eE]/.test(t)) return NaN                    // 1e3 — не лік для вучня
  t = t.replace(/[\u2212\u2013\u2014]/g, '-')      // − – — → -
  t = t.replace(/[\s\u00a0\u202f]/g, '')
  t = t.replace(/,/g, '.')
  t = t.replace(/[^0-9.\-]/g, '')                   // адзінкі па краях: «12 руб»
  if (!/^-?\d{1,9}(\.\d{1,6})?$/.test(t)) return NaN
  return parseFloat(t)
```

| Увод | Значэнне | Прымаецца | Каментарый |
|---|---|---|---|
| `12,5` | 12.5 | так | коска = дзесятковы падзельнік |
| `12.5` | 12.5 | так | кропка таксама |
| ` 12,50 ` | 12.5 | так | прабелы ігнаруюцца |
| `12 руб` / `12,5 см` | 12 / 12.5 | так | адзінкі па краях дапушчальныя |
| `−7` (U+2212) | −7 | так | мінус-знак нармалізуецца (баг цяперашняга кода) |
| `–7` / `—7` | −7 | так | en/em dash таксама |
| `-7` | −7 | так | звычайны дэфіс |
| `0,750` | 0.75 | так | лішнія нулі не шкодзяць |
| `1e3` | NaN | не | не ператвараць у 13 або 1000 |
| `1-2` | NaN | не | два мінусы/мінус не ў пачатку |
| `-` / `` / `abc` | NaN | не | паказ «Увядзі лік 🙂», спроба не ўлічваецца |
| `9999999999999` | NaN | не | больш за 9 цэлых лічбаў |
| `0` | 0 | так | нуль — сапраўдны адказ, не блытаць з пустым полем |

Пры адмове (NaN): паказаць «Увядзі лік 🙂», **не** лічыць адказ спробай (не мяняць `total`), поле застаецца актыўным.

### 3.7 Узроўні і складанасць

`levelFor(scope)`: § → `subs[key].level`; раздзел → `topics[ch].level`; `mix` → 5. Значэнне заўсёды цэлае 1..10, па змаўчанні 3, пры адсутнасці даных — 3.

Правілы чытання матрыцы:

4. §, дзе ўсе радкі NEW (калонка «§ цалкам новыя»), — зона найбольшай рызыкі: іх правярае tester у першую чаргу.

## 6. Мадэль даных v3 (кантракт back → front)

Канон — `docs/data-model-sub.md` (зона `docs/schema`). Ніжэй — абавязковы мінімум, які front спажывае.

```js
// localStorage['mt6_state_v3']
{
  "xp": 0, "level": 1, "solved": 0, "correct": 0,
  "streakDays": 0, "lastDay": null, "todayCount": 0, "todayDate": null, "dailyGoal": 10,
  "topics": { "decimals": {"correct": 14, "total": 20, "level": 4}, /* … 6 раздзелаў */ },
  "subs":   { "decimals:S1": {"correct": 4, "total": 5, "level": 5}, /* … па факце адказаў */ },
  "badges": ["first"], "hadPerfectSession": false,
  "history": [{"ts": 1795678000, "scope": "decimals:S1", "correct": 9, "total": 10}],
  "settings": {"sound": true}

```

| Функцыя | Подпіс | Семантыка |
|---|---|---|
| `getSubStats(scope)` | → `{correct,total,level,acc}` | `acc = total ? Math.round(correct/total*100) : null`; для раздзела — агрэгат `topics`; для `mix` → `null` |
| `addResult(scope, ok)` | → `{level,correct,total}` | улічвае **адзін** адказ; калі scope — §, піша `subs[key]`; заўсёды піша `topics[chapter]`; узровень ±1 (DEC-8) |
| `levelFor(scope)` | → 1..10 | § → `subs`; раздзел → `topics`; `mix` → 5 |
| `normalizeScope(raw)` | → scope \| null | §3.1 |

Інварыянты: ключы `subs` ⊆ 38 кананічных; `correct ≤ total`; узровень цэлы 1..10; кожны адказ дадае роўна 1 у `topics[ch].total` і 1 у `subs[key].total`; сума `subs.correct` па раздзеле ≤ `topics[ch].correct` (легасі-адказы v2 жывуць толькі ў `topics`).

Міграцыя: няма `v3` → чытаць `v2`, захаваць усе агульныя палі і `topics` (узроўні), `subs = {}`, запісаць `v3`, `v2` пакінуць; `v3` сапсаваны → `defaultState()`; `localStorage` недаступны → праца ў памяці з `console.warn`. Скід прагрэсу выдаляе абодва ключы.

## 7. Алгарытм сесіі

```
gensForScope(scope):
  if scope == 'mix'      → усе генератары ўсіх §§
  if scope мае ':'       → GEN_BY_SUB[scope]
  інакш                  → канкатэнацыя GEN_BY_SUB[scope+':'+sn] для ўсіх sn з SUBS[scope]

chooseQuestion(scope):
  if scope == 'mix': ch = раздзел па вазе слабасці (як цяпер); pool = gensForScope(ch)
  else:              ch = chapterOf(scope); pool = gensForScope(scope)
  d = levelFor(ch)                        // § → узровень §, раздзел → узровень раздзела
  for 5 спробаў: g = pool[random]; try return g(d) catch continue
  return null                             // → памылка генерацыі, банер

startSession(scope):
  scope = normalizeScope(scope); if (!scope) → home + warn
  session = {scope, answered:0, correct:0, total:10, startXp:S.xp, perfect:true}

recordAnswer(ok):                          // адзін раз на пытанне
  key = GEN_SCOPE.get(current.fn)          // зваротная мапа fn → 'ch:SN', будуецца адзін раз
  addResult(key, ok)                       // піша і subs, і topics — роўна па 1
  session.answered++; if (ok) session.correct++ else session.perfect=false
  XP: +5+2·d пры правільным (як цяпер)

finishSession():
  grade = clampGrade(correct/total); паказ выніку; #res-scope = подпіс scope
```

`GEN_SCOPE` будуе front пры ініцыялізацыі: праход па `GEN_BY_SUB`, `map.set(fn, key)`. Гэта адзіны спосаб даведацца § для пытання ў рэжыме `mix` без змены кантракту генератара.

## 8. Acceptance criteria

**AC-1. Пакрыццё 38/38.** Для кожнага з 38 §§ з `SUBS.md` існуе `GEN_BY_SUB['ch:SN']` з ≥1 генератарам; ключоў роўна 38, лішніх няма.
*Праверка:* `node tools/smoke-subs.js` → радок «§§: 38», няма `FAIL няма генератара`, няма `FAIL лішні ключ`.

**AC-2. Кантракт генератара.** Кожны выклік вяртае аб'ект `{q:string, a:number, hint:string}`; `q` 5..300 сімвалаў, `a` канечны лік, `hint` 6..200; незапоўненых маркераў шаблону і `NaN/undefined/Infinity/e+` няма.
*Праверка:* харнес, 5 значэнняў `d` × 40 розыгрышаў на генератар → 0 `FAIL`.

**AC-3. Лікавы адказ і акругленне.** `a` цэлы або ≤2 знакі пасля коскі (`decimals:S9` — ≤3; `decimals:S5` — ≤4); `|a| ≤ 1e6`; адзінкі — у `q`, не ў `a`.
*Праверка:* харнес (`a з >3 знакамі`, `a не лік`, `a завялікі`).

**AC-4. Разнастайнасць.** На 200 розыгрышаў пры `d = 5` кожны генератар дае ≥20 розных `q`; кожны § мае ≥2 генератары (мінімум 1 — блакуючы, 2 — мэта); няма двух § з аднолькавым наборам пытанняў.
*Праверка:* харнес, блок `WARN` — павінен быць пусты.

**AC-5. Сесія па кожным § без памылак.** Для ўсіх 38 §§ сімулюецца сесія з 10 пытанняў: кожнае пытанне з пула гэтага §, без выключэнняў, адказ вяртаецца праз увод (round-trip `fd(a) → parseAns`), ніякіх `null`/`NaN`.
*Праверка:* харнес друкуе «сесій: 45, пытанняў: 450» і «OK: 0 памылак»; асобна 38 §-сесій без `FAIL`.

**AC-6. Сесіі па раздзелах і mix.** 6 раздзелаў і `mix` даюць па 10 пытанняў з адпаведнага пула без выключэнняў.
*Праверка:* той жа харнес (45 = 38 + 6 + 1).

**AC-7. Шлях вучня.** Галоўная → клік карткі раздзела → бачная §-панэль з усімі §§ гэтага раздзела → клік пункта § → квіз.
*Праверка:* у браўзеры: пасля кліку бачны `#screen-sub` і роўна N пунктаў (10/7/4/9/3/5); пасля кліку «§3» бачны `#screen-quiz`, у полі пытання — заданне гэтага §.

**AC-8. «Усе §» = увесь раздзел.** Кнопка запускае сесію са scope раздзела; у загалоўку «· усе §»; пытанні належаць розным §§ раздзела.
*Праверка:* 30 пытанняў запар, усе з `GEN_BY_SUB['decimals:S*']`; у сярэднім ≥3 розныя § на 10 пытанняў.

**AC-9. Загаловак пытання.** Для §-сесіі — «{emoji} {раздзел} · §N»; для раздзела — «· усе §»; для mix — «Змяшаная трэніроўка».
*Праверка:* клік па кожным тыпе сесіі; тэкст `#q-topic` адпавядае табліцы 5.7.

**AC-10. Захаванне і міграцыя.** Даныя пішуцца ў `mt6_state_v3`; пасля перазагрузкі працэнты §§ і ўзроўні тыя ж; даныя `mt6_state_v2` мігруюць без страт (xp, solved, badges, topics), `v2` не выдаляецца.
*Праверка:* set `v2` уручную (`xp:120, solved:40`) → выдаліць `v3` → reload: `home-xp = 120`, `home-solved` у дашбордзе 40, `subs = {}`; 3 адказы ў § → `subs['decimals:S1'].total = 3`; reload → 3 захаваліся.

**AC-11. Статыстыка § у панэлі.** Да першага адказу — «нов.»; пасля першага правільнага — «100% · ур. 4» (3+1); пасля памылкі ўзровень −1 (не ніжэй за 1); працэнт акруглены да цэлага.
*Праверка:* 1 правільны → 1 памылка → 2 правільныя: у пункце «67% · ур. 4».

**AC-12. Нуль памылак кансолі.** Праход галоўная → §-панэль → 3 адказы → вынік → дашборд → назад: `console` без `error`/`uncaught`. Адсутнасць `generators.js` дае банер, а не белы экран.
*Праверка:* DevTools Console; асобна перайменаваць `generators.js` і перазагрузіць.

**AC-13. Мабільнасць.** На 320×568 і 390×844 няма гарызантальнага скролу; тап-зоны пунктаў § ≥44 px; тэксты не абрэзаныя.
*Праверка:* DevTools device mode, `document.documentElement.scrollWidth <= window.innerWidth`.

**AC-14. Беларуская мова.** Усе новыя тэксты беларускія; няма «undefined», «null», пустых подпісаў, лацінскіх слоў у інтэрфейсе.
*Праверка:* візуальны агляд усіх экранаў + пошук `undefined` у DOM.

**AC-15. Без рэгрэсу гейміфікацыі.** XP расце, бэйдж «Першы крок» выдаецца, дзённая мэта лічыцца, гук перамыкаецца, конфеті на адзнаку ≥8, «Скінуць прагрэс» выдаляе `v3` і `v2` і вяртае даныя да пачатковых.
*Праверка:* сцэнар у браўзеры + праверка `localStorage` пасля скіду.

**AC-16. Увод.** Усе 13 варыянтаў з табліцы 3.6 паводзяць сябе як паказана; адмова не павялічвае `total`.
*Праверка:* ручны прагон + 3 праграмныя выклікі `parseAns('−7')`, `parseAns('1e3')`, `parseAns('1-2')`.

**AC-17. Няма падвойнага ўліку.** Адзін адказ павялічвае `topics[ch].total` і `subs[key].total` роўна на 1; другі Enter/клік нічога не павялічвае.
